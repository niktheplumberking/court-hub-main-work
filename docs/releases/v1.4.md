# Court Hub v1.4: copy, sharing and search

Previous release: v1.3 (`0cbfc6804c58e5f6e333bcc2231f46c7eac93cf4`).

## Scope

Authored display strings have no em dashes. Existing CMS and product copy is normalized on read; no records are rewritten. URLs, image files, order/payment values, original catalogue images and source records are retained. This preference also applies to UI labels in the admin.

The static share card is `public/brand/court-hub-share-v1.4.png` (1200 × 630). It uses the header's Inter Bold wordmark and brand colours. `scripts/generate-share-image.mjs` reproduces the artwork; the bundled Inter font includes its SIL OFL license. All core pages and product routes receive a complete canonical Open Graph/Twitter configuration. WhatsApp's cached previews may persist until it refetches the URL; this release does not send messages or clear another service's cache.

English/Arabic canonicals, reciprocal language alternates, both product languages in the sitemap, a semantic shop heading, actual product/offer/breadcrumb markup, business identity and four visible quick answers provide the on-site SEO/AEO/GEO work. FAQ markup uses exactly the displayed answers. There are no fabricated ratings, GTINs, certifications, shipping speeds, return policies or event claims. Unfinished tournament pages and legal drafts remain noindex.

The business address in the organization data matches the published Contact Us and footer: 51A Street, Al Warqa 3, Dubai, UAE. Keep it synchronized if the business edits that address.

Google's guidance applies normal SEO foundations to AI search, with no required special AI text file or special schema. These changes do not guarantee rankings or inclusion in an answer engine. Search Console/Business Profile ownership, third-party listings and external indexing are not changed by this release.

## Product visibility

The existing admin product Status dropdown includes Draft (hidden). Saving Draft hides the product while retaining its record/images; selecting Active restores it. v1.4 also filters the three curated 3D hero models against active database products, independently of the newest-eight rail. An empty showcase renders no product rather than a dead link. No actual product status is changed during validation.

## Validation

```sh
node scripts/test-seo-copy.cjs
node scripts/test-product-upload.cjs
npm run lint
npm run build
python3 scripts/audit-public-seo.py http://127.0.0.1:3001
```

The read-only audit requests crawler HTML using a WhatsApp user agent, validates metadata in the initial head, checks sitemap language pairs and product offer data, verifies visible FAQ parity, finds display em dashes and checks the share PNG dimensions. Repeat against `https://courthub.ae` after publication. Inspect English/Arabic mobile layouts and the actual brand card visually. Do not claim an actual sent WhatsApp preview or measured search ranking from this audit.

## Rollback

Read `/var/backups/courthub/v1.4-backup-path` for the protected production backup directory. Restore its v1.3 source and `.next` build, restart only the `courthub` PM2 process, verify the public shop and save the PM2 configuration. No database rollback is needed for v1.4; keep the approved v1.3 high-resolution product image records.
